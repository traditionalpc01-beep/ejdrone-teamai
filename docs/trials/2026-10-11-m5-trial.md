## 3. 暴露并已修掉的缺陷（都有回归用例）

### 缺陷 1 · 卸载后 hook 文件差一个字节（承诺没做到）

- **现象**：`~/.claude/settings.json` 卸载后比备份多一个结尾换行；内容语义完全相同。
- **根因**：`src/hooks.ts` 硬写 `JSON.stringify(…, null, 2) + '\n'`，而成员这份文件是 **4 空格缩进、结尾无换行**。
- **为什么算缺陷**：我们的承诺是"只动我们那一条"。对用 dotfiles 做 git 管理的成员，这会凭空产生一份"我没改过但变了"的 diff。
- **修法**：读取原文时记下缩进宽度与结尾换行，写回时沿用（`render()`）。
- **回归用例**：`test/hooks.test.ts > 格式回环`（4 空格无换行、2 空格有换行两条都断言"装完再卸逐字节等于原文"）。

### 缺陷 2 · 卸载留下 `{}` 孤儿文件

- **现象**：试验前不存在 `~/.codex/hooks.json`，卸载后它躺在那儿，内容是 `{}`。
- **根因**：`removeHook` 摘掉自己的条目后照样写回文件。
- **修法**：摘完只剩空对象 → 删文件（空对象不承载任何成员信息，留着只会让人问"这是谁写的"）；只要还剩成员内容就永不删。
- **回归用例**：`test/hooks.test.ts`（空对象被删 / 含 `model` 键时保留）、`test/integration/failure.test.ts`（真链路里 hook 文件整个是我们造的话卸载后消失；成员自己先有配置时只摘我们那条）。

## 4. 已知行为与未修项（不算 bug，但要知道）

- **空目录只报告不删除**：卸载会打印 `留下空目录 …`。原因是分不清是谁建的 —— `~/.trae/rules` 是 Trae 原生目录，删了就是动成员的目录；`~/.claude/rules` 是我们建的。分不清就不删，改成说清楚。
- **`~/.codex/AGENTS.md` 卸载后是 0 字节空文件**：区块被撤掉、文件保留（1.0 定的语义，本次照旧）。
- **codex 的 hook 仍是 PROBE**：我们写了 `~/.codex/hooks.json`，`doctor` 报 PASS 只证明"文件里有我们那条"，不证明 Codex 会执行它。真机只见 `config.toml`。
- **detect 会误报**：`~/.pi`、`~/.hermes` 这类目录可能因别的软件存在而被判"已装"。16 工具后这个面变大了，`init` 交互勾选仍然由成员自己确认，非交互 `--agent` 由成员自己写。
- **6 个工具的 rules 不下发**（`codebuddy/workbuddy/pi/openclaw/hermes/kiro`）：它们没有可写的 markdown rules 载体，`rulesMode: none`。宁可少投递，也不往它不读的位置硬写文件。
