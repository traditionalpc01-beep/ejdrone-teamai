## 3. 暴露并已修掉的缺陷（都有回归用例）

### 缺陷 1 · 含明文 token 的文件没被收紧到 0600（安全）

- **现象**：`~/.claude.json` 被写入 `Bearer SENTINEL-m6-live-token` 之后仍是 `-rw-r--r--`。
- **根因**：`applyPlan` 有 `resolvedValuePaths` 这个入参，但**没有任何调用方传它** —— 一条为红线而生的代码路径其实是死线路。
- **修法**：解析过 `${VAR}` 这件事只有 planMcp 知道，所以让它把 `merge.hasResolvedValue` 标在投递上，apply 据此收紧。
  不让 apply 猜内容像不像密钥 —— 猜会把不含密钥的文件也一起改权限。
- **回归**：`test/core/apply.test.ts > 含已解析值的 merge 投递必须收紧权限`（0644→0600，且成员条目不动；不带标记时权限不变）。
- **重跑真机**：同一次 init 后 `~/.claude.json` 变为 `-rw-------`。

### 缺陷 2 · 卸载把成员自己的空目录说成"可能是我们建的"

- **现象**：试验里报出 `留下空目录 ~/.trae-cn/user_rules`，而我全程没勾选过 trae-cn。
- **根因**：`uninstall` 有意遍历全注册表（要撤掉所有工具的 hook），空目录报告跟着用了全表的根。
- **修法**：只报我们这次真删过文件的根。

### 缺陷 3 · 写 `referencesEnvVar` 时踩到的全局正则陷阱（编码期自纠）

`VAR_RE` 带 `/g`，对它调 `.test()` 会推进 `lastIndex`，连续判断会时漏时不漏。判存在改用不带 `g` 的副本，
并加"连续调用三次结果一致"的用例钉住。

### 上一轮修的两处，本轮真机验证到效果

- `uninstall` 之前完全不认条目级合并，会把我们投的 server 留在成员文件里；现在按账本 `managedKeys` 反向合并
  `desired={}` 只撤自己那几条 —— 第 8 步五个文件逐字节回原样就是它的证据。
- 坏 `mcp.yaml` 的停发与退出码（端到端用例覆盖，真机本轮未复现故障）。

## 4. 已知行为与未修项（不算 bug，但要知道）

- **权限只收紧不回松**：卸载后 `~/.claude.json` 留在 0600（备份是 0644）。要"回松"就得把原权限记进账本，
  而 0600 不会让成员丢访问、反而防止同机其他人读到明文 token。本轮试验我按备份把权限手动改回了 0644。
- **`status` 把本机私有 server 也列在"待推送"里**：措辞上确实容易读成"这些都该推"，但 `push --all` 明确不含 MCP，
  且紧邻的下一行就给了 `push --mcp <名字>` 的用法。改措辞要连带动命令面那批用例，本轮判为不值得，留给后续统一复核。
- **TOML 落点不反向采集**：`push --mcp` 遇到只在 `~/.codex/config.toml` 里的 server 会点名文件并给条目形状，要求手写入库。
  投递侧我们对 TOML 只做受控行级拼接，为采集再补一个 TOML 解析器就是把它请回来。
- **成员文件里的畸形键会被当条目列出**（`mcpServers` 套 `mcpServers`）：只读扫描，不解释、不改动。
- **codex 的 `[mcp_servers.*.http_headers]` 子表形态**按 Codex 文档写入，但 Codex 是否真按这个键加载未证（保留 PROBE）。
