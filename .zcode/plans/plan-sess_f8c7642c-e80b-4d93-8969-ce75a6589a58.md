# ejdrone 2.1：tags 标签订阅（对标 teamai-cli，全 6 类资源）

## 一、语义定义（写入新 spec）

- **声明**：文件类资源（skills/rules/agents/docs/learnings）在 frontmatter 写 `tags: [a, b]`；MCP 条目在 `mcp*.yaml` 的 server 上写 `tags: [a]`。tag 名复用 `isValidResourceName`（小写字母数字 `-`/`_`，≤120）。
- **订阅**：成员本地 config 新增 `subscribedTags: string[]`，经 `ejdrone tags subscribe/unsubscribe <tags...>` 维护（逗号可分隔，并集/差集语义；未知 tag 允许写入但 WARN，镜像 rolesSet 对未知角色的处理）。
- **下发规则**（条目级，不是 namespace 级）：根条目全员；ns 条目 = 「角色激活的 namespace」∪「带任一已订阅标签的条目」。未打标且 ns 未激活 → 不投。退订后 active 集缩小，走既有删除链路自动清理，无需新机制。
- **同名裁决继承既有语义，零特判**：tag 激活的 ns 条目与角色激活的另一 ns 条目同名 → 既有「同名冲突停发该 kind」；与根条目同名 → 既有「ns 整体替换根」。根条目上的 tags 无效但无害。
- **管理命令**：`ejdrone tags add <kind> <名字> <tag...>` / `tags remove <kind> <名字> <tag...>`——改仓库 frontmatter / mcp 条目并开 MR；无变化时报「无需提交」（镜像 readme 的 no-op 处理）。kind 解析复用 `cli/kinds.ts` 的 SPELLINGS。

## 二、冻结契约增量（4 个字段，全部 additive，不改任何既有签名）

1. `Resource.tags?: string[]`（types.ts）
2. `McpServerDef.tags?: string[]`（types.ts）
3. `Config.subscribedTags: string[]`（types.ts + state.ts schema `.default([])` 保证旧 config 兼容 + stringifyConfig + init.ts 字面量）
4. `ResolveInput.activeTags?: string[]`（可选，既有调用点零改动）

## 三、实现清单（按依赖顺序）

**1) 契约与采集层**
- `core/types.ts`：上述 4 字段 + 注释（tags 只做加法豁免、不参与替换方向）。
- `core/resources.ts`：新增 `parseFrontmatterTags(content)`（splitFrontmatter + yaml，复用既有解析器）；`collectSkills/collectRules/collectFlatMd` 采集时解析进 `Resource.tags`；坏形状（非字符串数组）→ 当作无 tags + warning 线程进 `Snapshot.warnings`（collectResources 返回值扩展 warnings，非冻结类型）。
- `core/mcp.ts`：`serverEntrySchema` 加 `tags: z.array(z.string()).optional()`；`toServerDef`/`resolveServerDef` 透传。
- `state.ts` + `cli/init.ts`：config schema/序列化/字面量。

**2) 裁决层（单点收口）**

**3) 投递与视图（三个调用点统一走谓词）**

**4) 命令面**
