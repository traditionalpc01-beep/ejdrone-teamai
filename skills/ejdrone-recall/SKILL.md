# ejdrone-recall：动手前先问一句"团队有没有现成的说法"

个人的经验只有被下过的人读到才算团队的知识。这条技能规定一个很便宜的动作：**开工前先做一次
相关性预检**，有相关资料就去读，没有就直接干 —— 不要凭记忆猜团队的规范。

## 怎么做

1. 从任务里挑 1–3 个**最短且最能代表主题**的关键词（中英文都可以，多个词用空格分隔）。
   关键词要具体：`kafka 消费积压` 比 `问题` 好得多。
2. 预检（只看分数，不会打印文件内容，适合在会话里自动跑）：

   ```bash
   ejdrone recall --check "kafka 消费积压"
   ```

   - 输出 `RELEVANT score=<n> threshold=<n>`、退出码 0 → 有相关资料，进第 3 步。
   - 输出 `NOT_RELEVANT score=<n> threshold=<n>`、退出码 1 → 团队没有现成说法，正常开工。
   - 输出「团队知识镜像还不存在」→ 这台机器还没 `ejdrone pull` 过，别把它当成"团队没有资料"。
3. 取命中清单与片段（±2 行上下文，最多 5 条，按相关度排序：标题 ×3 / tags ×2 / 正文 ×1）：

   ```bash
   ejdrone recall "kafka 消费积压"
   ```

   需要脚本化处理时加 `--json`。按打印出来的**绝对路径**去读整份文件，只读第 1 条通常就够。
4. 读到与当前任务相关的约定时，**照它执行**，并在回答里说出依据是哪一份（报路径即可）。
   文档之间打架时不要自己折中：把两份路径都点名出来，请用户或负责人裁决。

## 边界

- 检索范围只有本机 `~/.ejdrone/knowledge/` 里的**投递镜像**，镜像内容 = 你订阅的角色该拿到的那部分。
  检索不到不等于团队没有，可能是你的角色不对，或该文档还没合入 —— 这时候问人，不要改代码去猜。
- 这个动作是**只读**的：不写文件、不记账、不投票。
- 想沉淀新经验是另一件事：写一份 learning 交给 `ejdrone contribute`，不要就地改镜像里的文件
  （你改的那份 pull 会保留并点名，但团队拿不到）。
